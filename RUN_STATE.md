## Commands

```bash
cd /workspace/Split-Federated-Merging-Learning/Sources
scripts/journal_experiments/start_lanes.sh status        # lanes alive?
tmux attach -t ehsfp-lanes                               # watch (detach: Ctrl-b d)
cat results/campaign/status.json | head -60              # counts, running, ETA, builds
ls results/journal_v1/.markers/*.lock                    # running runs
ls results/journal_v1/.markers/*.failed                  # failed runs (never auto-retried)

touch results/journal_v1/.markers/STOP_ALL               # SAFE STOP: lanes finish their current run, then exit and stay down
rm results/journal_v1/.markers/STOP_ALL; scripts/journal_experiments/start_lanes.sh   # restart / resume
scripts/campaign/collect_all.sh manual                   # collect + tables + figures + both PDFs now
python scripts/campaign/build_queue.py                   # regenerate the queue (after editing the generator)
rm results/journal_v1/.markers/<eid>.failed              # re-admit one failed run after fixing its cause
```

An interrupted run (lane killed, host restart) leaves a lock whose PID is dead. The next lane takes the
lock over and restarts the run **from scratch**. No runner saves optimizer, scheduler, RNG, episodic-memory
or sampler state mid-run (`checkpoint.pt` holds best-model weights only), so a mid-run resume would not be
scientifically valid.

Cron (`crontab -l`, lines tagged `# SFML`) does three things: every 10 min `start_lanes.sh` restarts dead
lanes; every 2 h at even KST hours `collect_all.sh cron` runs; at the same time a bounded Claude review runs,
only when something needs attention. In addition (2026-10-16), each 10-min `start_lanes.sh` tick calls
`scripts/campaign/collect_if_new.sh`, which runs `collect_all.sh new_results` whenever a run has finished
since the last collection, so tables/LaTeX/PDFs/status refresh within ~10 min of any new result.
Every collection then runs `scripts/campaign/update_report.py`, which writes what changed (new runs and
their metrics, cells filled, figures updated, failures, progress/ETA) to `Sources/results/campaign/LATEST_UPDATE.md`
and appends it to `UPDATES.md`.

To resume interactively: `cd /workspace/Split-Federated-Merging-Learning && claude` and ask it to "read
RUN_STATE.md and Sources/results/campaign/status.json, then handle failures".
